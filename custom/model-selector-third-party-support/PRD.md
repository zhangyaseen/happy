# PRD: 模型选择器支持第三方模型

## 背景

Happy App 支持多种 agent flavor（Claude, Codex, Gemini, Agy 等），每种 flavor 在模型选择器中有一组预设的模型选项。用户通过 Claude Code 的 `~/.claude/settings.json` 可以配置第三方模型提供商（如 Qwen、本地模型等），但 Happy App 的模型选择器目前无法反映这些自定义配置。

## 用户场景

### 场景 1：使用第三方模型的用户

**角色**: 开发者，配置了 Qwen 作为 Claude Code 的后端模型

**当前行为**:
1. 用户在 `~/.claude/settings.json` 中配置了 `model: "qwen3.7-plus"`
2. 通过 `claude --model qwen3.7-plus` 启动会话可以正常工作
3. 打开 Happy App，模型选择器显示：Fable 5.1, Fable 5, Opus 5, Opus 5 [1M], Sonnet 5
4. 选择其中任何一个都会切换到对应的 Anthropic 模型，而不是用户配置的第三方模型
5. 用户无法在 UI 中看到或选择自己配置的第三方模型

**期望行为**:
1. 模型选择器显示用户通过 settings.json 配置的模型（如 `qwen3.7-plus`）
2. 如果有多个可用模型，全部列出供选择
3. 当前使用的第三方模型应被正确标记为"已选中"
4. 如果没有自定义模型，保留默认回退行为

### 场景 2：使用本地模型的用户

**角色**: 开发者，使用 Ollama 运行本地模型

**期望行为**:
1. 模型选择器中显示本地模型名称（如 `llama3`, `mistral` 等）
2. 能正常切换和选择

### 场景 3：混合使用

**角色**: 开发者，有时用 Anthropic 官方模型，有时用第三方

**期望行为**:
1. 模型选择器同时显示 Anthropic 默认模型和第三方模型
2. 通过 provider 分组清晰区分

## 功能需求

### FR-1: 显示自定义模型

当 agent 通过 ACP 报告了自定义模型列表时，模型选择器应优先显示这些模型，而非硬编码列表。

### FR-2: 显示当前选中的第三方模型

即使无法获取完整的模型列表，当前会话使用的第三方模型也应出现在选择器中（至少作为一行），标记为当前选中。

### FR-3: Provider 分组

模型应按 provider 分组显示（Anthropic / OpenAI / Custom / 等），方便用户识别。

### FR-4: 模型切换

用户从选择器中选择第三方模型后，应正确通知 agent 切换模型。

### FR-5: 回退行为

当没有自定义模型数据时，保留当前的硬编码回退列表（Anthropic 默认模型）。

## 非功能需求

### NFR-1: 向后兼容

已有的 Anthropic 默认模型选择行为不应受到影响。

### NFR-2: 性能

模型列表的加载不应增加明显的 UI 延迟。

## 验收标准

| # | 条件 | 预期结果 |
|---|------|----------|
| AC-1 | 用户在 settings.json 配置了第三方模型，启动 Claude 会话 | App 模型选择器显示该第三方模型 |
| AC-2 | 用户通过选择器切换到第三方模型 | 后续对话使用该第三方模型 |
| AC-3 | 用户没有配置第三方模型 | 显示默认的 Anthropic 模型列表（现有行为） |
| AC-4 | 第三方模型当前正在使用 | 该模型标记为"已选中"状态 |
| AC-5 | agent 报告了多个自定义模型 | 所有模型都出现在选择器中 |
